# omk (oh my knowledge) - Glossary & Domain Boundaries

이 문서는 프로젝트 내에서 사용되는 핵심 개념과 용어들을 명확히 정의하여, 의사소통 시 발생하는 다의성과 혼선을 원천적으로 방지하기 위해 작성되었습니다. 모든 시스템 구성 요소, 기획 문서 및 코드는 이 문서에 정의된 고유 명칭과 역할을 기준으로 작성해야 합니다.

## 1. 핵심 객체 및 시스템 경계 (Core Entities & Boundaries)

동일한 개념을 지칭할 때 혼동을 막기 위해 아래의 명칭들을 엄격하게 구분하여 사용합니다.

### 1.1 omk (oh my knowledge)
- **정의:** 시스템 전체(로컬 지식 금고) 및 프로젝트의 비전 자체를 아우르는 포괄적 공식 명칭입니다.

### 1.2 omk CLI (Core Binary)
- **정의:** 사용자의 시스템에 단일 실행 파일(예: `omk`) 형태로 설치되어, 로컬 파일 시스템 제어, 검색 엔드포인트 제공, 그리고 터미널 명령 처리를 전담하는 핵심 백엔드 애플리케이션입니다.
- **역할 (코디네이션 제어권 집중):** 스킬 동작의 정합성 보장, 워크플로우 통제, 데이터 유효성 검사 등 **모든 조율(Coordination)과 통제에 대한 실질적인 제어권을 중앙집중적으로 독점**합니다. AI의 임의적 우회나 비정상적인 접근을 차단하고 결정론적 룰을 강제합니다.

### 1.3 omk Skill (omk 스킬)
- **정의:** AI 에이전트가 `omk CLI`와 안전하게 상호작용할 수 있도록 시스템이 제공하는 **"지침(Instruction)과 통제된 도구(Tool)의 결합체"**입니다.
- **특징:** 어딘가에 종속되는 단순 플러그인이 아닙니다. omk 시스템의 본질적인 인터페이스 패키지로서, 인간 사용자가 `omk CLI`를 통해 자신의 환경(특정 AI 에이전트 환경 등)에 이 스킬을 "설치(Provisioning)"하여 활성화합니다.

## 2. 상호작용 주체 (Actors)

### 2.1 AI Agent (AI 에이전트)
- **역할:** 환경에 설치된 "omk Skill"의 지침을 읽고 런타임에 이를 **실체화(Instantiation)**하여 동작하는 비결정론적 주체입니다.
- **한계:** 지식을 탐색하고 대화를 이끌어가는 판단 주체이지만, 파일 접근이나 정보의 수정과 같은 실질적인 시스템 제어는 반드시 `omk CLI`가 제공하는 도구의 엄격한 코디네이션 통제 안에서만 수행해야 합니다.

### 2.2 Human User (인간 사용자 / 개발자)
- **역할:** `omk CLI` 터미널 명령어를 통해 자신의 시스템이나 AI 에이전트 환경에 "omk Skill"을 설치(`omk install`)하고, 시스템 전반의 환경을 설정하며 관리하는 주체입니다.

## 3. 핵심 아키텍처 개념 (Core Concepts)

### 3.1 Proactive Grounding (선제적 교차 노출)
- AI Agent가 "omk Skill"을 활용해 로컬 금고를 자발적으로 조회하고, 과거의 지식을 현재의 대화 컨텍스트에 엮어 사용자에게 먼저 제시하는 omk 프로젝트의 궁극적인 목표이자 경험입니다.

### 3.2 Local Vault (로컬 지식 금고)
- 마크다운 파일 형태로 사용자의 지식이 저장되는 물리적 로컬 디렉터리 및 검색 인프라를 의미합니다.
